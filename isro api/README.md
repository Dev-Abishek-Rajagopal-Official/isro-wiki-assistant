# isro api – FastAPI backend for the ISRO multi-agent assistant

Auth (JWT), conversations with multiple threads, WebSocket streaming of answers **and** live AgentState,
full history (events + AgentState snapshots per step), token usage, health. Uses the LangGraph agent from
`../isro agentic orchestration` (installed as an editable package).

## Run

```
# infrastructure (in ../isro agentic orchestration): Postgres :5432, Redis :6379, pgAdmin :5050
docker compose up -d
# MCP servers (in ../isromcp): knowledge base, Launch Library, Wikidata, CelesTrak on :8101-8104
uv run python run_http_servers.py
# API
uv sync
copy .env.example .env          # set JWT_SECRET (>= 32 chars), DATABASE_URL, REDIS_URL
uv run alembic upgrade head
uv run python run.py            # http://127.0.0.1:8000  (docs: /docs)
uv run python examples/ws_client.py   # end-to-end demo
uv run pytest -q                # API tests (separate test DB + Redis DB 15, agent disabled)
```

`run.py` sets the Windows selector event loop (required by psycopg async) and keeps uvicorn from replacing it.

## Layout

```
app/
  main.py                 app factory + lifespan (DB, Redis, agent, run service in app.state)
  core/                   config (pydantic-settings), security (argon2id, JWT), redis client
  db/                     SQLAlchemy models, async session
  schemas/                Pydantic request/response models
  api/deps.py             session, current user (JWT + Redis revocation + cached user)
  api/routes/             auth, conversations, threads, usage, health, ws
  services/
    agent.py              orchestrator lifecycle (API stays up with 503s if the agent cannot start)
    runs.py               one run: thread lock -> runs row -> stream agent -> publish -> llm_calls -> totals
    hub.py                WebSocket fan-out over Redis pub/sub
    tokens.py             Redis token store (refresh rotation, access revocation, logout everywhere)
    titles.py             conversation names from a dedicated LLM
    usage.py              usage aggregation
    cache.py, repository.py
migrations/               Alembic
tests/                    auth, ownership, usage, WebSocket protocol
examples/ws_client.py     end-to-end client
```

## Data model (PostgreSQL)

```
users ─< conversations ─< threads ─< runs ─┬─< llm_calls     every LLM call: role, model, tokens, latency, rate-limit headroom
                                           └─< agent_events  every AgentState change + progress event (ordered)
threads.id = LangGraph thread_id -> checkpoint tables: full AgentState after every graph step
```

- **conversation**: a workspace; `title` is generated by an LLM from the first question (`title_source=generated`)
  unless the user names it (`user`); `created_at`, `updated_at`, `last_activity_at`.
- **thread**: independent agent memory inside a conversation; many per conversation.
- **run**: one question: status, answer, agents used, seconds, token totals.
- **AgentState** carries `run_usage` (this question) and `thread_usage` (thread lifetime), each with totals and
  breakdowns `by_role` and `by_model`.

## Redis

| Key / channel | Purpose |
|---|---|
| `auth:rt:{sha256}` | refresh token -> user (TTL 7 days, single use: rotated on refresh) |
| `auth:revoked:{jti}` | revoked access token (until its expiry) – logout |
| `auth:revoked_before:{user}` | access tokens issued earlier are invalid – logout everywhere |
| `cache:user:{id}`, `cache:usage:*`, `cache:health` | caches (5 min / 60 s / 10 s) |
| `lock:run:{thread}` | one active run per thread (across instances) |
| `lock:title:{conversation}` | one title generation per conversation |
| `ws:thread:{id}`, `ws:user:{id}` | pub/sub channels feeding WebSockets |

## Auth

`POST /auth/register` (email, full_name, password ≥ 8 chars with letters + digits) ->
`POST /auth/login` -> `{access_token (8 h), refresh_token (7 days)}`. Send `Authorization: Bearer <access>` on every
call; WebSockets authenticate with their first message. `POST /auth/refresh` rotates, `POST /auth/logout`,
`POST /auth/logout-all`, `GET /auth/me`. Another user's resources always return 404.

## REST

| | |
|---|---|
| `POST/GET /conversations`, `GET/PATCH/DELETE /conversations/{id}` | DELETE = archive (`include_archived=true` to list) |
| `POST/GET /conversations/{id}/threads`, `GET/PATCH/DELETE /threads/{id}` | thread detail = messages + current AgentState + usage + runs |
| `GET /threads/{id}/runs`, `GET /runs/{id}` | runs; a run with every LLM call |
| `GET /threads/{id}/events?after_id=&run_id=` | stored event log (replay / polling) |
| `GET /threads/{id}/states` | AgentState snapshot after every graph step |
| `POST /threads/{id}/ask`, `POST /threads/{id}/ask-audio` | non-streaming ask (also published live to sockets) |
| `GET /usage/me?from=&to=&group_by=` | requests, success/error, latency p50/p95, LLM calls, tokens (input/output/reasoning/cached), latest rate-limit headroom; group by `day/model/role/node/conversation/thread` |
| `GET /usage/conversations/{id}`, `GET /usage/threads/{id}` | same, scoped |
| `GET /health` | DB, Redis, agent, MCP servers, Qdrant, LLM/Speech config |

## WebSocket `/ws`

```
-> {"type":"auth","token":"<JWT>"}                      <- auth_ok | auth_failed (+ close 4401)
-> {"type":"ask","thread_id":"…","question":"…","client_msg_id":"…"}     <- accepted {run_id}
-> {"type":"ask_audio","thread_id":"…","audio_b64":"…","filename":"q.wav","content_type":"audio/wav"}
-> {"type":"subscribe","thread_id":"…","after_id":0}   <- subscribed, replayed events ("replay":true), replay_done
-> {"type":"unsubscribe","thread_id":"…"}  -> {"type":"cancel","run_id":"…"}  -> {"type":"ping"}
```

Run messages (one envelope `{type, thread_id, run_id, seq, node, event_id, ts, data}`):
`run_started`, `transcribing`, `transcribed`, `router_decision` (`data.structured` = next_agent, task, reason and
every agent's content), `agent_progress` (`step`: agent_started / query_rewritten / tool_called / tool_result /
agent_content), `llm_call`, `state_update` (delta), `state` (**full current AgentState** incl. usage), `token`
(answer chunk), `final_answer`, `run_finished` (run + thread usage), `run_cancelled`, `error`, `busy`.
User messages: `conversation_titled`. One socket can run and watch many threads; one active run per thread.
Runs continue if the socket drops; reconnect and `subscribe` with the last `event_id` to catch up.

## Verified (examples/ws_client.py against the running server)

Two threads asked concurrently on one socket (CelesTrak route 12 s, RAG route 19 s), streamed tokens + full
AgentState messages, one LLM-generated conversation title, thread history with AgentState snapshots, replay of all
stored events on a new socket, usage totals equal to the sum of llm_calls, logout revokes the access token.
